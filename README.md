# Tekti

Tekti — консольный агент, который проверяет документ с требованиями до начала разработки. Он читает `.md`, `.markdown`, `.txt` и текстовые `.pdf`. Сканы без текстового слоя не поддерживаются.

Агент выделяет из документа отдельные требования. Затем он проверяет каждое требование и весь набор по критериям качества из **ISO/IEC/IEEE 29148:2018** (п. 5.2.5, 5.2.6) и **IEEE Std 830-1998** (п. 4.3). Ещё он ищет в тексте инструкции, адресованные модели или проверяющему (`embedded_instruction`).

Результат — отчёт на русском языке:

- замечания, каждое с дословной цитатой из документа;
- уточняющие вопросы, у каждого указан адресат (роль);
- вердикт о готовности к разработке и тестированию. Его считает код, а не модель.

**Отчёт по документу организаторов** («Уведомление о расходах по карте»): [`submission/report.md`](submission/report.md). Полные данные этого прогона: [`submission/report.run.json`](submission/report.run.json). Прогон сделан 27.11.2026 в режиме `board` с моделями по умолчанию на коммите `d0affea`.

## Быстрый старт

Нужны Python **3.12+** и менеджер пакетов [`uv`](https://docs.astral.sh/uv/).

1. Установите зависимости и создайте файл настроек:
   ```bash
   uv sync
   cp .env.example .env
   ```
2. Впишите в `.env` свои ключи, один из двух вариантов:
   ```bash
   # Вариант 1: три ключа поставщиков. Так получен отчёт в submission/.
   OPENAI_API_KEY=...
   ANTHROPIC_API_KEY=...
   GOOGLE_API_KEY=...        # ключ Gemini API из Google AI Studio; можно назвать GEMINI_API_KEY

   # Вариант 2: один ключ OpenRouter вместо трёх.
   OPENROUTER_API_KEY=...
   ```
3. Проверьте, что модели отвечают. Скрипт отправляет каждой модели один короткий запрос и не выводит ключи:
   ```bash
   uv run python scripts/smoke_providers.py
   ```
4. Запустите проверку:
   ```bash
   uv run tekti path/to/requirements.md path/to/report.md
   ```

Отчёт появится в `path/to/report.md`. Рядом, в `path/to/report.run.json`, Tekti сохранит полные данные прогона. Проверка документа организаторов заняла 5,4 минуты и стоила около $1.55.

Tekti читает ключи из `.env` в текущей папке или из переменных окружения. Переменные окружения главнее `.env`. Ключи не выводятся на экран, не пишутся в журнал и не попадают в отчёт.

## Два способа запуска

### Вариант 1. Три ключа поставщиков

Tekti вызывает API OpenAI, Anthropic и Google напрямую. Этим способом получен отчёт в `submission/`.

Можно задать не все три ключа. Тогда коллегия соберётся из доступных поставщиков, а нарезку, группировку и вопросы возьмёт одна из доступных моделей. С двумя ключами в коллегии будет два семейства, и режим `board` будет работать как `standard`. Для полной коллегии из трёх семейств нужны все три ключа.

### Вариант 2. Один ключ OpenRouter

[OpenRouter](https://openrouter.ai) даёт доступ к моделям OpenAI, Anthropic и Google по одному ключу. Ключ создаётся на [openrouter.ai/keys](https://openrouter.ai/keys). Tekti обращается к OpenRouter как к OpenAI-совместимому API и собирает ту же коллегию из трёх семейств.

Модели в этом варианте: `openai/gpt-6.1-terra`, `anthropic/claude-haiku-5.5`, `google/gemini-4-carbon`. Роли распределены так же, как в варианте 1. Если отдельный вызов Gemini не удался, Tekti повторяет его на `google/gemini-3.5-flash-lite`.

Если заданы и ключи поставщиков, и ключ OpenRouter, Tekti берёт ключи поставщиков. Чтобы включить OpenRouter явно, задайте `TEKTI_PROVIDER=openrouter`.

Этот путь проверен меньше, чем вариант 1. Полный прогон через OpenRouter сделан 27.11.2026 только на бесплатной модели и небольшом тестовом документе: успешны 24 вызова из 25. Идентификаторы и параметры трёх моделей по умолчанию сверены с каталогом OpenRouter. Прогона на самих этих трёх моделях через OpenRouter не было.

Если модель вернёт ответ в неверном формате, Tekti отбросит этого рецензента, назовёт его в паспорте отчёта и продолжит прогон.

### Сравнение вариантов

| | Три ключа поставщиков | Один ключ OpenRouter |
| :--- | :--- | :--- |
| Что нужно завести | три аккаунта и три ключа | один аккаунт и один ключ |
| Кто видит документ | только поставщики моделей | OpenRouter и поставщики моделей |
| Цена | по прайсу поставщиков | прайс поставщиков плюс комиссия OpenRouter при пополнении |
| Насколько проверено | все прогоны, включая отчёт в `submission/` | полный прогон только на бесплатной модели |

Оговорка: это по одному прогону с каждой стороны, а прогон коллегии был лучшим в своей серии. В других прогонах коллегия находила от 14 до 20 критичных дефектов, и результат одной модели (16) попадает в этот диапазон. Устойчивые отличия — число подтверждённых замечаний, независимая перекрёстная проверка и та же цена. Чтобы уверенно назвать разницу в полноте, нужно по несколько прогонов с каждой стороны.

Повторить сравнение:

```bash
C=google:gemini-4-carbon
TEKTI_PANEL=$C TEKTI_SEGMENTER=$C TEKTI_MERGE_MODEL=$C TEKTI_QUESTION_WRITER=$C \
  uv run tekti path/to/requirements.md path/to/single.md --mode fast
```

## Как устроена проверка

```text
ingest → segment → rules → panel → adjudicate → questions → verdict → report
 код       LLM      код     LLM     код + LLM      LLM        код      код
```

1. **`ingest`** (код). Читает `.md`, `.markdown`, `.txt` и текстовые `.pdf` (через `pymupdf`). Делит текст на пронумерованные блоки и запоминает для каждого путь разделов. Каждая строка таблицы становится отдельным блоком (`TABLE_ROW`).
2. **`segment`** (LLM). Выделяет требования и делит составные требования на атомарные. Код проверяет, что цитата каждого требования дословно есть в документе.
3. **`rules`** (код, отключается флагом `--no-rules`). Детерминированные проверки из `tekti.rules`: пустые разделы и заглушки, незаполненные атрибуты и чек-листы, размытые формулировки, единицы измерения, типы полей запроса и ответа, HTTP-методы и статусы, встроенные инструкции (`embedded_instruction`).
4. **`panel`** (LLM, параллельно). Коллегия проверяет документ с пяти углов: `functional`, `api_contract`, `data_integration`, `tester`, `developer`. Каждый угол проверяет модель каждого семейства. В режиме `board` это 15 рецензентов.
5. **`adjudicate`** (код и LLM). Сводит замечания рецензентов и решает, какие из них подтверждены. Правила ниже.
6. **`questions`** (LLM). Превращает подтверждённые замечания в уточняющие вопросы.
7. **`verdict`** (код). Разработку можно начинать, если нет подтверждённых критичных замечаний. Тестирование можно начинать, если можно начинать разработку и нет критичных или существенных замечаний по критериям «Проверяемость» (`verifiable`) и «Валидируемость набора» (`set_validatable`).
8. **`report`** (код). Собирает отчёт на русском только из данных прогона (`Run`). В отчёте семь разделов: паспорт прогона, нарезка требований, проверка каждого требования, проверка всего набора, уточняющие вопросы, сводка, итог.

### Когда замечание подтверждено

- Код проверяет, что каждая цитата есть в документе (без учёта лишних пробелов). Замечание без найденной цитаты отклоняется.
- Повторяющиеся замечания склеиваются: сначала по требованию и критерию, затем отдельным проходом модели группировки. Этот проход делает до двух кругов.
- Замечание подтверждено, если его подняли два семейства моделей или больше. Замечание, которое нашло правило, тоже подтверждено.
- Замечание одного семейства уходит на перекрёстную проверку к модели другого семейства. Проверяющая модель не видит критичность, которую указал рецензент, и оценивает её сама. Остаётся меньшая из двух оценок.
- Чтобы отклонить замечание, нужны два проверяющих из двух разных семейств. Если первый отклонил, а второй подтвердил, замечание остаётся. Если вызов проверяющей модели не удался, замечание тоже остаётся.
- Отклонённые замечания не попадают в текст отчёта. Они сохраняются в данных прогона вместе с обоснованием.

Кто проверяет замечание одного семейства:

| Замечание подняла только | Первая проверка | Вторая проверка, если первая отклонила |
| :--- | :--- | :--- |
| GPT | Claude | Gemini |
| Claude | GPT | Gemini |
| Gemini | GPT | Claude |

Gemini стоит в этом порядке последней, потому что сейчас отвечает медленнее всех.

### Уточняющие вопросы

- Модель пишет как можно меньше вопросов, которые вместе закрывают все замечания. Если несколько замечаний снимает один ответ, у них общий вопрос.
- У каждого вопроса есть адресат (роль) и указано, что он блокирует.
- На каждое противоречие пишется отдельный вопрос «или — или» с вариантами ответа из текста документа.
- Каждое критичное замечание закрыто хотя бы одним вопросом.
- В отчёте вопросы, которые закрывают критичные замечания, показаны полностью, но не больше 20. Остальные вопросы собраны в одну таблицу.

## Модели по умолчанию

Коллегия состоит из трёх независимых семейств моделей от трёх поставщиков.

| Роль | Модель | Поставщик |
| :--- | :--- | :--- |
| Коллегия, место 1 (в режиме `fast` единственное) | `gpt-6.1-terra` | OpenAI |
| Коллегия, место 2 | `claude-haiku-5-5` | Anthropic |
| Коллегия, место 3 | `gemini-4-carbon`; запасные `gemini-4-hydrogen` и `gemini-3.5-flash-lite` | Google |
| Нарезка требований (`TEKTI_SEGMENTER`) | `claude-haiku-5-5`, без рассуждений | Anthropic |
| Группировка повторов (`TEKTI_MERGE_MODEL`) | `gpt-6.1-terra` | OpenAI |
| Уточняющие вопросы (`TEKTI_QUESTION_WRITER`) | `gpt-6.1-terra` | OpenAI |

`TEKTI_PANEL` меняет только коллегию. Нарезка, группировка и вопросы остаются на своих моделях, чтобы прогоны можно было сравнивать.

### Если Gemini перегружена

Модели Gemini 4 иногда отвечают «high demand». На этот случай есть две замены.

- **Перед прогоном.** Tekti отправляет `gemini-4-carbon` короткий запрос. Если модель дважды не ответила за 45 секунд, её место на весь прогон занимает следующая модель из цепочки: сначала `gemini-4-hydrogen`, затем `gemini-3.5-flash-lite`. Какая модель работала, видно в паспорте отчёта. Время ожидания задаёт `TEKTI_PROBE_TIMEOUT`, значение `0` отключает эту проверку.
- **Во время прогона.** Если отдельный вызов Gemini 4 не удался или не уложился во время, Tekti один раз отправляет тот же запрос в `gemini-3.5-flash-lite`. Рецензент не теряется. Неудачная попытка и замена записываются в данные прогона.

### Глубина рассуждений

Глубину рассуждений для каждого этапа задаёт `TEKTI_REASONING`. Значения по умолчанию:

| Этап | Уровень |
| :--- | :--- |
| Нарезка (`segment`) | `off` |
| Коллегия (`panel`) | `medium`, у Gemini `low` |
| Перекрёстная проверка (`challenge`) | `low` |
| Группировка (`merge`) | `low` |
| Вопросы (`questions`) | `medium` |

Рассуждения расходуют лимит ответа. Поэтому Tekti добавляет к лимиту запас: `low` +4000 токенов, `medium` +12000, `high` +24000.

### Состав коллегии и цена

Место Anthropic занимает малая модель Haiku 5.5. Её голос слабее: в отчёте из `submission/` у неё 51 исходное замечание, у GPT 97, у Gemini 71. Три семейства при этом остаются независимыми.

На место Google можно поставить `gemini-3.5-flash-lite`. Тестовый прогон с ней 26.11.2026 стоил около $0.56 и занял 4,5 минуты. Но третий голос тогда заметно слабее: Flash-Lite дала 12 исходных замечаний, а Gemini 4 Carbon в прогоне того же дня дала 66.

Таблица цен и расчёт лежат в комментарии в `src/tekti/config.py`. Стоимость прогона по его токенам считает `tekti.config.estimate_cost(run.calls)`.

## Другие способы запуска

### Только бесплатный ключ Gemini

Нужен только ключ из Google AI Studio: [aistudio.google.com/apikey](https://aistudio.google.com/apikey). Оплата и аккаунт AWS не нужны.

```bash
GOOGLE_API_KEY=...
```

```bash
uv run tekti path/to/requirements.md path/to/report.md --mode fast
```

Все роли выполняет `gemini-4-hydrogen`. Если она перегружена, её заменяет `gemini-3.5-flash-lite`. У обеих моделей есть бесплатный уровень. Из-за его лимитов Tekti по умолчанию делает не больше 2 параллельных вызовов.

**Этот вариант заметно слабее полной коллегии.** В нём одно семейство моделей, и перекрёстную проверку делает то же семейство. Кроме того, по условиям Google данные бесплатного уровня могут использоваться для улучшения продуктов Google. Не отправляйте так конфиденциальные документы.

### Amazon Bedrock

Tekti берёт стандартные учётные данные AWS: `AWS_PROFILE` или `AWS_ACCESS_KEY_ID` и `AWS_SECRET_ACCESS_KEY`. Регион по умолчанию `us-east-1`. Bedrock включается явно через `TEKTI_PROVIDER=bedrock`. Без этой переменной Tekti выбирает Bedrock сам, если не задан ни один ключ поставщика и нет ключа OpenRouter.

```bash
TEKTI_PROVIDER=bedrock uv run tekti path/to/requirements.md path/to/report.md
```

Модели Bedrock по умолчанию заданы в `DEFAULT_BENCH` в `src/tekti/config.py`. Состав такой, потому что у учётной записи автора не было доступа к более сильным моделям в Bedrock.

- Нарезка требований и уточняющие вопросы: `us.anthropic.claude-haiku-4-5-20251001-v1:0` (Anthropic).
- Коллегия (в режиме `board` первые три): `anthropic:us.anthropic.claude-haiku-4-5-20251001-v1:0`, `openai:openai.gpt-oss-120b-1:0`, `mistral:mistral.mistral-large-3-675b-instruct`.
- Только для перекрёстной проверки: `qwen:qwen.qwen3-vl-235b-a22b`, `moonshot:us.moonshotai.kimi-k3.1`.

### Любой OpenAI-совместимый API

Подходит, например, локальная Ollama. В этом режиме `TEKTI_PANEL` и `TEKTI_BASE_URL` обязательны.

```bash
TEKTI_PROVIDER=openai_compatible
TEKTI_BASE_URL=http://localhost:11434/v1
TEKTI_API_KEY=...            # если API требует ключ
TEKTI_PANEL=qwen:qwen3:32b
```

## Настройки

### Какие настройки главнее

1. Явные `TEKTI_PANEL`, `TEKTI_SEGMENTER`, `TEKTI_MERGE_MODEL`, `TEKTI_QUESTION_WRITER`.
2. `TEKTI_PROVIDER`, если он задан: `vendors`, `openrouter`, `bedrock` или `openai_compatible`. Он выбирает набор моделей по умолчанию.
3. Иначе (`auto`) Tekti берёт ключи поставщиков, если задан хотя бы один. Если их нет, берёт `OPENROUTER_API_KEY`. Если нет и его, берёт Bedrock.

Если задан `TEKTI_GATEWAY_URL` (шлюз автора), в пункте 3 Tekti выбирает шлюз раньше ключей поставщиков. Жюри эту переменную задавать не нужно, подробнее в конце документа.

### Формат записи модели

```text
[провайдер:][семейство:]model_id
```

Провайдер говорит, через что вызывать модель: `openai`, `anthropic`, `google` (API поставщика), `bedrock` или `openai_compatible`. По семейству Tekti считает голоса и выбирает проверяющую модель. Если семейство не указано, Tekti определит его по идентификатору модели.

В `TEKTI_PANEL` модели перечисляются через запятую, по одной на семейство, сильнейшие первыми. Провайдеров можно смешивать:

```bash
TEKTI_PANEL=google:gemini-4-carbon,openai:gpt-6.2-sol,bedrock:mistral:mistral.mistral-large-3-675b-instruct
```

Префиксы `openai:`, `anthropic:` и `google:` означают API поставщика только в режиме поставщиков (заданы ключи поставщиков или `TEKTI_PROVIDER=vendors`). В режиме `bedrock` это имя семейства. Идентификатор вида `<поставщик>.<модель>` в обоих режимах означает модель Bedrock. Поэтому `openai:openai.gpt-oss-120b-1:0` и `us.anthropic.claude-…` вызываются через Bedrock.

### Параметры командной строки

```text
uv run tekti <input> <report> [--mode {fast,standard,board}] [--run-json <path>] [--no-rules]
```

| Параметр | Описание |
| :--- | :--- |
| `input` | Файл с требованиями: `.md`, `.markdown`, `.txt` или `.pdf`. |
| `report` | Куда записать отчёт в Markdown (`.md`). |
| `--mode {fast,standard,board}` | Размер коллегии: `fast` берёт первое семейство из коллегии, `standard` первые два, `board` первые три. По умолчанию `board`. |
| `--run-json <path>` | Куда сохранить данные прогона. По умолчанию `<report>.run.json`. |
| `--no-rules` | Не запускать детерминированные проверки правилами (`tekti.rules`). |

### Переменные окружения

| Переменная | Назначение и значение по умолчанию |
| :--- | :--- |
| `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GOOGLE_API_KEY` (или `GEMINI_API_KEY`) | Ключи для прямых вызовов поставщиков. Не выводятся и не пишутся в журнал. |
| `OPENROUTER_API_KEY` | Один ключ OpenRouter вместо трёх ключей поставщиков. Не выводится и не пишется в журнал. |
| `TEKTI_PROVIDER` | Набор моделей по умолчанию: `auto` (по умолчанию; порядок выбора описан выше), `vendors`, `openrouter`, `bedrock` или `openai_compatible`. |
| `TEKTI_PANEL` | Модели коллегии через запятую в формате `[провайдер:][семейство:]model_id`. Обязательна при `TEKTI_PROVIDER=openai_compatible`. |
| `TEKTI_SEGMENTER` | Модель для нарезки требований. |
| `TEKTI_MERGE_MODEL` | Модель для группировки повторяющихся замечаний. С ключами поставщиков и с OpenRouter по умолчанию `gpt-6.1-terra`. В остальных режимах по умолчанию та же модель, что пишет вопросы. |
| `TEKTI_QUESTION_WRITER` | Модель для уточняющих вопросов. |
| `TEKTI_REASONING` | Глубина рассуждений по этапам, например `panel=high,challenge=low,google:panel=medium`. Этапы: `segment`, `panel`, `challenge`, `merge`, `questions`, `default`. Уровни: `off`, `low`, `medium`, `high`. |
| `TEKTI_PROBE_TIMEOUT` | Сколько секунд ждать ответа Gemini при проверке перед прогоном (по умолчанию `45`, две попытки). `0` отключает проверку. |
| `TEKTI_LENSES` | Углы проверки через запятую. По умолчанию все пять: `functional,api_contract,data_integration,tester,developer`. |
| `TEKTI_MAX_PARALLEL` | Сколько вызовов моделей идут одновременно. По умолчанию `6`, или `2`, если единственный поставщик — Google. |
| `TEKTI_MAX_OUTPUT_TOKENS` | Лимит ответа на один вызов модели (по умолчанию `12000`). К нему добавляется запас под рассуждения, см. «Глубина рассуждений». |
| `TEKTI_BACKEND` | Способ вызова: `strands` (по умолчанию) или `converse`. `converse` работает только для моделей Bedrock, остальные модели всё равно идут через Strands. |
| `TEKTI_REGION` | Регион AWS для Bedrock. По умолчанию `AWS_REGION`, затем `AWS_DEFAULT_REGION`, затем `us-east-1`. |
| `TEKTI_BASE_URL` | Адрес OpenAI-совместимого API, например `http://localhost:11434/v1` для Ollama. |
| `TEKTI_API_KEY` | Ключ для `TEKTI_BASE_URL`. Не выводится и не пишется в журнал. |

Переменные шлюза автора (`TEKTI_GATEWAY_*`, `TEKTI_GITHUB_CLIENT_ID`) описаны в последнем разделе.

## Запуск через Docker

Соберите образ:

```bash
docker build -t tekti .
```

Запустите проверку файла из папки `./data` с настройками из `.env`:

```bash
docker run --rm --env-file .env -v "$PWD/data:/data" tekti /data/requirements.md /data/report.md
```

Флаги CLI, например `--mode fast` или `--no-rules`, добавьте в конец команды:

```bash
docker run --rm --env-file .env -v "$PWD/data:/data" tekti /data/requirements.md /data/report.md --mode fast
```

## Тесты и оценка по эталону

### Тесты и линтер

Тесты детерминированы. Они не ходят в сеть и не вызывают модели.

```bash
uv run pytest
uv run ruff check src tests
```

### Оценка по эталону (`evals/gold.yaml`)

Скорер сравнивает замечания прогона с эталонным набором дефектов документа организаторов. Он считает полноту по всем и по критичным дефектам в двух вариантах:

- мягкая (`loose`): совпадает цитата;
- строгая (`strict`): совпадает цитата и критерий совместим.

Ещё он показывает долю подтверждённых замечаний, которых нет в эталоне. Несколько прогонов он выводит рядом, с временем вызовов из `Run.calls`.

```bash
uv run python -m tekti.evals submission/report.run.json
uv run python -m tekti.evals path/to/fast.run.json path/to/board.run.json
```

Флаги: `--gold <path>`, `--format {markdown,json}`, `--out <path>`, `--json-out <path>`, `--label <name>`.

Скорер показывает и оценку стоимости прогона по таблице цен из `src/tekti/config.py`.

## Шлюз автора (жюри не нужен)

В репозитории есть код шлюза (`gateway/`). Это функция AWS Lambda, через которую можно было запускать Tekti на ключах автора после входа через GitHub (`tekti login`). Шлюз ограничивал число запросов и пускал только логины из списка.

**Шлюз не развёрнут:** стек удалён 27.11.2026. Для проверки он не нужен, оба способа запуска выше работают со своими ключами.

К шлюзу относятся команды `tekti login`, `tekti whoami`, `tekti logout` и переменные:

| Переменная | Назначение |
| :--- | :--- |
| `TEKTI_GATEWAY_URL` | Адрес шлюза. Если он задан, все модели OpenAI, Anthropic и Google идут через шлюз, даже когда заданы свои ключи. |
| `TEKTI_GATEWAY_TOKEN` | Токен владельца шлюза, только для автора. Главнее сохранённой сессии GitHub. Не выводится и не пишется в журнал. |
| `TEKTI_GITHUB_CLIENT_ID` | Client ID OAuth-приложения GitHub для `tekti login`. По умолчанию встроенный. |

Устройство шлюза описано в [`gateway/README.md`](gateway/README.md).
