# Tekti

**Tekti** — CLI ИИ-агент для статического ревью документов с требованиями до начала разработки (поддерживаются `.md`, `.markdown`, `.txt` и текстовые `.pdf` без OCR).

Агент выделяет требования из документа, проверяет каждое требование и весь набор целиком по закрытому перечню критериев качества **ISO/IEC/IEEE 29148:2018** (п. 5.2.5, 5.2.6) и **IEEE Std 830-1998** (п. 4.3), а также выявляет встроенные инструкции, адресованные модели или проверяющему (`embedded_instruction`). По итогам прогона формируется отчёт на русском языке с точными дословными цитатами из документа, адресными уточняющими вопросами и детерминированным вердиктом о готовности к разработке и тестированию.

**Отчёт по документу организаторов** («Уведомление о расходах по карте») лежит в [`submission/report.md`](submission/report.md); полные данные того же прогона — в [`submission/report.run.json`](submission/report.run.json). Прогон выполнен 27.11.2026 в режиме `board` с моделями по умолчанию на коммите `d0affea` (он указан в паспорте отчёта).

## Быстрый старт

Нужны Python **3.12+** и менеджер пакетов [`uv`](https://docs.astral.sh/uv/).

```bash
uv sync
```

Запустить проверку можно двумя способами, оба — со своими ключами:

1. **Три ключа поставщиков** (OpenAI, Anthropic, Google) — вызовы идут напрямую в API каждого поставщика. Так сделан прогон, отчёт которого лежит в `submission/`.
2. **Один ключ OpenRouter** — те же три модели через одну точку входа и один счёт.

Команда проверки в обоих случаях одна:

```bash
uv run tekti path/to/requirements.md path/to/report.md
```

### Вариант 1 — свои ключи поставщиков

1. Скопируйте образец настроек и впишите ключи:
   ```bash
   cp .env.example .env
   ```
   ```bash
   OPENAI_API_KEY=...
   ANTHROPIC_API_KEY=...
   GOOGLE_API_KEY=...        # ключ Gemini API из Google AI Studio; подойдёт и GEMINI_API_KEY
   ```
2. Проверьте, что модели отвечают (один короткий запрос на модель; ключи не выводятся):
   ```bash
   uv run python scripts/smoke_providers.py
   ```
3. Запустите проверку:
   ```bash
   uv run tekti path/to/requirements.md path/to/report.md
   ```

Ключи читаются из `.env` или из окружения, не выводятся, не логируются и не попадают в отчёт. Вызовы идут напрямую в API поставщиков; шлюз автора в этом варианте не участвует.

Если задана только часть ключей, коллегия собирается из доступных поставщиков (с двумя ключами — два семейства, режим `board` тогда работает как `standard`), а роли переходят к доступной модели. Полная коллегия из трёх семейств требует все три ключа.

### Вариант 2 — один ключ OpenRouter

[OpenRouter](https://openrouter.ai) даёт доступ к моделям OpenAI, Anthropic и Google по одному ключу. Tekti обращается к нему как к OpenAI-совместимой точке входа и собирает ту же коллегию из трёх семейств.

1. Создайте ключ на [openrouter.ai/keys](https://openrouter.ai/keys) и впишите его в `.env`:
   ```bash
   OPENROUTER_API_KEY=...
   ```
2. Проверьте, что модели отвечают:
   ```bash
   uv run python scripts/smoke_providers.py
   ```
3. Запустите проверку:
   ```bash
   uv run tekti path/to/requirements.md path/to/report.md
   ```

Модели: `openai/gpt-6.1-terra`, `anthropic/claude-haiku-5.5`, `google/gemini-4-carbon` (при сбое отдельного вызова — `google/gemini-3.5-flash-lite`); роли распределены так же, как в таблице ниже. Если заданы и ключи поставщиков, и ключ OpenRouter, используются ключи поставщиков; `TEKTI_PROVIDER=openrouter` включает OpenRouter явно.

Что стоит знать, выбирая между вариантами:

| | Три ключа поставщиков | Один ключ OpenRouter |
| :--- | :--- | :--- |
| Что нужно завести | три аккаунта и три ключа | один аккаунт и один ключ |
| Кто видит документ | только поставщики моделей | OpenRouter и поставщики моделей |
| Цена | по прайсу поставщиков | прайс поставщиков плюс комиссия OpenRouter при пополнении |
| Насколько проверено | все прогоны и отчёт в `submission/` | полный прогон через OpenRouter выполнен 27.11.2026 на бесплатной модели и небольшом тестовом документе (24 из 25 вызовов успешны); идентификаторы трёх моделей по умолчанию и их параметры сверены с каталогом OpenRouter, но **на самих этих трёх моделях через OpenRouter прогон не выполнялся** |

Если в варианте 2 одна из моделей вернёт ошибку формата ответа, проверяющий будет отброшен и назван в паспорте отчёта, а прогон продолжится; вариант 1 — путь, которым получен отчёт в `submission/`.

### Модели по умолчанию

Коллегия — три независимых семейства моделей у трёх разных поставщиков; каждая модель вызывается через API своего поставщика (OpenAI, Anthropic, Google). Те же модели доступны через OpenRouter (вариант 2).

| Роль | Модель | Поставщик |
| :--- | :--- | :--- |
| Коллегия, место 1 (в режиме `fast` — единственное) | `gpt-6.1-terra` | OpenAI |
| Коллегия, место 2 | `claude-haiku-5-5` | Anthropic |
| Коллегия, место 3 | `gemini-4-carbon`; запасные — `gemini-4-hydrogen`, `gemini-3.5-flash-lite` | Google |
| Нарезка требований (`TEKTI_SEGMENTER`) | `claude-haiku-5-5`, без рассуждений | Anthropic |
| Группировка замечаний (`TEKTI_MERGE_MODEL`) | `gpt-6.1-terra` | OpenAI |
| Уточняющие вопросы (`TEKTI_QUESTION_WRITER`) | `gpt-6.1-terra` | OpenAI |

Явный `TEKTI_PANEL` меняет только коллегию: нарезка, группировка и вопросы остаются на своих моделях, чтобы прогоны можно было сравнивать.

Перекрёстную проверку (`challenge`) выполняет первая по порядку модель коллегии из семейства, которое замечание не поднимало: замечания GPT проверяет Claude, замечания Claude и Gemini — GPT, замечания, поднятые и GPT, и Claude, — Gemini. Gemini стоит последней, потому что сейчас отвечает медленнее всех.

Перед проверкой Tekti отправляет модели Google короткий запрос; если `gemini-4-carbon` дважды не ответила за 45 секунд (Google отвечает «high demand»), на весь прогон её заменяет следующая из цепочки `gemini-4-hydrogen` → `gemini-3.5-flash-lite`, и это видно в паспорте прогона (`TEKTI_PROBE_TIMEOUT`, `0` отключает проверку). Если во время прогона не удался отдельный вызов модели Gemini 4 (перегрузка или превышено время), этот же запрос один раз повторяется на `gemini-3.5-flash-lite`: проверяющий не теряется, а неудачная попытка и замена записываются в данные прогона.

Глубина рассуждений задаётся по этапам (`TEKTI_REASONING`, по умолчанию: нарезка — без рассуждений, коллегия — `medium`, у Gemini — `low`, перекрёстная проверка и группировка — `low`, вопросы — `medium`); к лимиту ответа автоматически добавляется место под рассуждения.

Честно о составе: место Anthropic занимает малая модель (Haiku 5.5), поэтому её голос слабее, чем у GPT и Gemini 4 Carbon; три семейства при этом остаются независимыми. Прогон `board` на документе организаторов 26.11.2026 с этими умолчаниями: все 15 проверок коллегии успешны, **7,4 минуты**, оценка стоимости **$1.54** (Google $0.86, OpenAI $0.61, Anthropic $0.07). Три перекрёстные проверки на Gemini 4 Carbon не уложились во время и были повторены на `gemini-3.5-flash-lite`. С `gemini-3.5-flash-lite` на месте Google прогон стоит около $0.56 и занимает 4,5 минуты, но третий голос заметно слабее (12 исходных замечаний против 66). Таблица цен и расчёт — в комментарии в `src/tekti/config.py`; `tekti.config.estimate_cost(run.calls)` считает стоимость по токенам прогона.

## Другие способы запуска

### Только бесплатный ключ Gemini (сокращённая коллегия)

Не требует оплаты и аккаунта AWS. Получите ключ в Google AI Studio: [aistudio.google.com/apikey](https://aistudio.google.com/apikey) и задайте только его:

```bash
GOOGLE_API_KEY=...
```

Все роли выполняет `gemini-4-hydrogen`, при перегрузке — `gemini-3.5-flash-lite` (у обеих есть бесплатный уровень; у `gemini-4-neon` его нет), параллельность по умолчанию снижена до 2 из-за лимитов бесплатного уровня. **Это заметно слабее полной коллегии:** одно семейство, перекрёстная проверка тем же семейством, нет независимых «вторых мнений». Кроме того, по условиям Google данные бесплатного уровня могут использоваться для улучшения продуктов Google — не отправляйте так конфиденциальные документы.

```bash
uv run tekti path/to/requirements.md path/to/report.md --mode fast
```

### Amazon Bedrock (прежний режим)

Использует стандартную цепочку учётных данных AWS (`AWS_PROFILE` или `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`, регион по умолчанию `us-east-1`). Включается явно `TEKTI_PROVIDER=bedrock` или сам собой, если не задан ни шлюз, ни ключи поставщиков.

Модели Bedrock по умолчанию (`DEFAULT_BENCH` в `src/tekti/config.py`; учётная запись автора не получила доступа к сильным моделям, отсюда состав):

- **Нарезка требований и уточняющие вопросы**: `us.anthropic.claude-haiku-4-5-20251001-v1:0` (Anthropic)
- **Коллегия** (в режиме `board` первые 3): `anthropic:us.anthropic.claude-haiku-4-5-20251001-v1:0`, `openai:openai.gpt-oss-120b-1:0`, `mistral:mistral.mistral-large-3-675b-instruct`; на скамейке для перекрёстной проверки — `qwen:qwen.qwen3-vl-235b-a22b`, `moonshot:us.moonshotai.kimi-k3.1`.

```bash
TEKTI_PROVIDER=bedrock uv run tekti path/to/requirements.md path/to/report.md
```

### Какие настройки главнее

1. Явные `TEKTI_PANEL`, `TEKTI_SEGMENTER`, `TEKTI_MERGE_MODEL`, `TEKTI_QUESTION_WRITER`.
2. `TEKTI_PROVIDER`, если задан (`vendors`, `openrouter`, `bedrock`, `openai_compatible`), выбирает набор умолчаний.
3. Иначе (`auto`): ключи поставщиков, если задан хотя бы один; иначе `OPENROUTER_API_KEY`; иначе Bedrock. (Шлюз автора, если задан `TEKTI_GATEWAY_URL`, главнее всех трёх — см. конец документа.)

### Формат записи модели

`[провайдер:][семейство:]model_id`, где провайдер — `openai`, `anthropic`, `google`, `bedrock` или `openai_compatible`. Модели разных провайдеров можно смешивать в одной коллегии:

```bash
TEKTI_PANEL=google:gemini-4-carbon,openai:gpt-6.2-sol,bedrock:mistral:mistral.mistral-large-3-675b-instruct
```

Прежняя запись `семейство:model_id` работает как раньше: `openai:openai.gpt-oss-120b-1:0` и `us.anthropic.claude-…` остаются моделями Bedrock в любом режиме (идентификатор вида `<поставщик>.<модель>` распознаётся как Bedrock). Префиксы `openai:`, `anthropic:`, `google:` означают API поставщика только в режиме поставщиков (шлюз, ключи или `TEKTI_PROVIDER=vendors`); в режиме `bedrock` это по-прежнему имя семейства.

## Куда сохраняется результат, параметры CLI и конфигурация

### Выходные файлы

- **Отчёт в Markdown на русском языке** — сохраняется по пути второго аргумента (`path/to/report.md`).
- **Полный JSON-слепок прогона (`Run`)** — автоматически сохраняется рядом с отчётом с расширением `.run.json` (`path/to/report.run.json`) или по пути, указанному в `--run-json`.

### Параметры командной строки (`tekti`)

```text
uv run tekti <input> <report> [--mode {fast,standard,board}] [--run-json <path>] [--no-rules]
```

| Параметр | Описание |
| :--- | :--- |
| `input` | Входной файл с требованиями (`.md`, `.markdown`, `.txt`, `.pdf`). |
| `report` | Путь для сохранения итогового отчёта в Markdown (`.md`). |
| `--mode {fast,standard,board}` | Режим коллегии: `fast` — 1-е семейство из `TEKTI_PANEL`; `standard` — первые 2; `board` — первые 3 (по умолчанию). |
| `--run-json <path>` | Явный путь для сохранения JSON-данных прогона (по умолчанию `<report>.run.json`). |
| `--no-rules` | Отключить детерминированный слой проверки правилами (`tekti.rules`). |

### Переменные окружения

Настройки загружаются из файла `.env` в текущей рабочей директории; системные переменные окружения имеют приоритет над `.env`.

| Переменная | Назначение и значение по умолчанию |
| :--- | :--- |
| `TEKTI_GATEWAY_URL` | Адрес шлюза; если задан, все модели OpenAI, Anthropic и Google идут через него (вход — `tekti login`). |
| `TEKTI_GATEWAY_TOKEN` | Токен владельца шлюза (только для автора); главнее сохранённой сессии GitHub. Не выводится и не логируется. |
| `TEKTI_GITHUB_CLIENT_ID` | Client ID OAuth-приложения GitHub для `tekti login` (по умолчанию встроенный). |
| `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GOOGLE_API_KEY` (или `GEMINI_API_KEY`) | Ключи для прямых вызовов поставщиков. Не выводятся и не логируются. |
| `OPENROUTER_API_KEY` | Один ключ OpenRouter вместо трёх ключей поставщиков. Не выводится и не логируется. |
| `TEKTI_PROVIDER` | Набор умолчаний: `auto` (по умолчанию: ключи поставщиков → OpenRouter → Bedrock), `vendors`, `openrouter`, `bedrock` или `openai_compatible`. |
| `TEKTI_BACKEND` | Бэкенд вызова: `strands` (по умолчанию) или `converse` (`converse` обслуживает только модели Bedrock, остальные идут через Strands). |
| `TEKTI_REGION` | AWS-регион для Bedrock (по умолчанию `AWS_REGION`, затем `AWS_DEFAULT_REGION`, затем `us-east-1`). |
| `TEKTI_PANEL` | Модели через запятую в формате `[провайдер:][семейство:]model_id` (по одной на семейство, сильнейшие первыми; см. «Формат записи модели»). Обязательна при `TEKTI_PROVIDER=openai_compatible`. |
| `TEKTI_SEGMENTER` | Модель для нарезки требований. |
| `TEKTI_MERGE_MODEL` | Модель для группировки повторяющихся замечаний (по умолчанию — модель уточняющих вопросов; в умолчаниях поставщиков — `gpt-6.1-terra`). |
| `TEKTI_QUESTION_WRITER` | Модель для формулировки уточняющих вопросов. |
| `TEKTI_LENSES` | Список углов проверки через запятую (по умолчанию все 5: `functional,api_contract,data_integration,tester,developer`). |
| `TEKTI_MAX_PARALLEL` | Максимум параллельных вызовов (по умолчанию `6`; `2`, если единственный поставщик — Google). |
| `TEKTI_MAX_OUTPUT_TOKENS` | Лимит выходных токенов на один вызов модели, включая рассуждения (по умолчанию `12000`). |
| `TEKTI_BASE_URL` | URL OpenAI-совместимого эндпоинта (для моделей `openai_compatible`, например `http://localhost:11434/v1` для Ollama). |
| `TEKTI_API_KEY` | API-ключ для `TEKTI_BASE_URL` (никогда не выводится и не логируется). |

## Как устроен конвейер проверки

```text
ingest → segment → rules → panel → adjudicate → questions → verdict → report
 код       LLM      код     LLM     код + LLM      LLM        код      код
```

1. **`ingest`** *(код)* — чтение `.md`/`.markdown`/`.txt` и текстовых `.pdf` (через `pymupdf`) в пронумерованные блоки с сохранением путей разделов и строк таблиц (`TABLE_ROW`).
2. **`segment`** *(LLM)* — выделение требований из документа, разбивка составных требований на атомарные подпункты и проверка дословности цитат.
3. **`rules`** *(код, отключается `--no-rules`)* — детерминированный слой (`tekti.rules`): поиск пустых разделов и заглушек, незаполненных атрибутов и чек-листов, размытых формулировок, сверка единиц измерения, типов полей запроса/ответа, HTTP-методов и статусов, а также защита от встроенных инструкций (`embedded_instruction`).
4. **`panel`** *(LLM, параллельно)* — проверка документа и выделенных требований коллегией из 5 ролевых углов (`functional`, `api_contract`, `data_integration`, `tester`, `developer`) на выбранных семействах моделей.
5. **`adjudicate`** *(код + LLM)* — проверка точного вхождения каждой цитаты в текст документа (после нормализации пробелов), дедупликация замечаний и перекрёстная проверка (`challenge`) моделью другого семейства для замечаний, поднятых только одним семейством.
6. **`questions`** *(LLM)* — группировка подтверждённых замечаний в приоритизированные уточняющие вопросы с указанием адресата (роли), вариантов ответа и того, что вопрос блокирует.
7. **`verdict`** *(код)* — детерминированный расчёт готовности к разработке (отсутствие подтверждённых критичных дефектов) и к тестированию (готовность к разработке и отсутствие блокирующих дефектов по критериям проверяемости и валидируемости).
8. **`report`** *(код)* — генерация 7-секционного отчёта на русском языке строго из данных `Run`:
   1. Паспорт прогона
   2. Как агент нарезал требования
   3. Проверка каждого требования
   4. Проверка всего набора требований
   5. Уточняющие вопросы
   6. Сводка
   7. Итог

## Запуск через Docker

Сборка образа:

```bash
docker build -t tekti .
```

Запуск проверки на локальных файлах из каталога `./data` с конфигурацией из `.env`:

```bash
docker run --rm --env-file .env -v "$PWD/data:/data" tekti /data/requirements.md /data/report.md
```

Дополнительные флаги CLI (например, `--mode fast` или `--no-rules`) передаются в конец команды:

```bash
docker run --rm --env-file .env -v "$PWD/data:/data" tekti /data/requirements.md /data/report.md --mode fast
```

## Тесты и оценка по эталонному набору (scorer)

### Офлайн-тесты и линтер

Тесты полностью детерминированы, работают без сети и вызовов LLM:

```bash
uv run pytest
uv run ruff check src tests
```

### Оценка качества по эталону (`evals/gold.yaml`)

Замер мягкой (`loose`, по совпадению цитат) и строгой (`strict`, совпадение цитат + совместимый критерий) полноты (recall) по всем и критичным дефектам, доли непокрытых замечаний, а также сравнение нескольких прогонов бок о бок с расчётом времени и стоимости по `Run.calls`:

```bash
uv run python -m tekti.evals runs/board.run.json
uv run python -m tekti.evals runs/fast.run.json runs/board-no-rules.run.json runs/board.run.json
```

## Шлюз автора (не используется для проверки жюри)

В репозитории есть шлюз (`gateway/`): функция AWS Lambda, которая позволяет запускать Tekti с ключами автора после входа через GitHub (`tekti login`), с лимитами запросов и списком допущенных логинов. Для сдачи он не нужен и сейчас **не развёрнут**: оба варианта запуска выше работают со своими ключами. Команды `tekti login`, `whoami`, `logout` и переменные `TEKTI_GATEWAY_*` относятся только к нему. Устройство, развёртывание и настройка описаны в [`gateway/README.md`](gateway/README.md).
