
## P1-md Markdown ingestion (main orchestrator)
- Built: `tekti.ingest.load` (dispatch .md/.markdown/.txt → markdown, .pdf → lazy `tekti.ingest.pdf.load_pdf` with a Russian "PDF support not installed" error, else a Russian error) and `ingest/markdown.py`, a line-based splitter (headings, paragraphs, list items, table rows, fenced code) with section paths and exact 1-based lines. Block text is the raw source text with markup kept (table rows keep their pipes, headings keep "###", list items keep "* "), because gold quotes cite markup.
- Verified: `uv run pytest tests/ingest` (6 passed); on local/requirements.md: 124 blocks, every block's normalized text is a substring of the normalized raw text, and every gold anchor/related quote is found in one block or two adjacent blocks.
- Not verified: PDF path end to end (pdf.py not present while I worked); nested lists, setext headings and HTML in Markdown are not handled specially (treated as paragraphs).

## P2 segmentation (main orchestrator)
- Built: `tekti.segment.split(doc, cfg) -> list[Requirement]` (one call, document as numbered blocks inside <document> in the user turn; instructions-only system prompt in `prompts/segment.py`). Code recomputes block ids from quote position, repairs quotes that only miss `**`/backtick markup, retries failing candidates once in one call, then drops; drops/retries are in `segment.last_result` (`SegmentResult.dropped`) or via `split_with_report`.
- Verified: `uv run pytest tests/segment` (7 passed) with a fake backend: id order R-001.. with children after parent, parent_id links, retry fixes, retry-then-drop, retry-call failure salvages a valid parent, exact-quote invariant.
- Not verified: no run against a real model (config.py/install_backend were not available); prompt quality and the 35-55 count on the organisers' document are untested. `src/tekti/prompts/` has no `__init__.py` (works as a namespace package); add one if packaging needs it.

## P5 adjudication (main orchestrator)
- Built: `tekti.adjudicate.merge(doc, requirements, raw, cfg, *, challenger_for=None)` (pass `tekti.config.challenger_for`; local default picks the first panel model of another family, same model in fast mode): quote check with markup-insensitive recovery of the exact quote, bucketing with folding, overlap union + one batched "merge" call per bucket, conservative cross-bucket pass (related criteria need matching evidence both ways), vote/merge, cross-family challenge with block+neighbours+section path and the whole document (if <= 60k chars), F-001.. ordering; rejected get their own X-001.. series. Side outputs: `last_stats` (incl. `challenges_failed`, `same_family_challenges`) and `last_question_drafts`. Prompts in `prompts/challenge.py`.
- Verified: `uv run pytest tests/adjudicate` (18 passed, fake backend); live once with config standard on 4 hand-made findings about local/requirements.md: after one prompt revision Ф-3/Ф-4 conflict and «в Алматы» ambiguity upheld as critical, the bogus "currency missing" and "no SMS" findings rejected with correct Russian reasoning.
- Not verified: a full panel run (hundreds of raw findings): merge-call quality and the cross-bucket pass on real reviewer output; cost of challenging every single-family finding.

## P4 review panel (main orchestrator)
- Built: `tekti.panel.review(doc, requirements, facts, cfg)` fans out every (lens, model) pair under `asyncio.Semaphore(cfg.max_parallel)`; a failing reviewer is recorded in `panel.last_dropped` / `panel.dropped()` as "lens/model_id: error" and the rest return. Prompts (Russian, instructions-only system turn, document in <document> in the user turn, invented-domain micro-example, explicit distant-part cross-check, per-lens method, a discarded `worksheet` scratch field so non-reasoning models actually do the cross-checks) live in `panel/prompts.py`; output schema in `panel/schema.py`. Code keeps only quotes found in the normalized document (repairing pure typographic drift: lost `**`/backticks, ё/е, dash and quote styles, to the exact document text), sets `block_id`, maps document ids like "Ф-1" to R-ids, strips unknown ids, drops findings with no evidence or an out-of-list criterion/severity; counts in `panel.stats()`.
- Verified: `uv run pytest tests/panel` (9 passed, fake backend); real run of the functional lens on Claude Haiku 4.5 (Bedrock) against local/requirements.md with the real segmenter's 39 requirements: 10 findings, 0 quotes dropped; after one prompt revision it raised the month-rule vs acceptance-row conflict, the one-push cap vs threshold-change conflict, goal vs one-minute NFR, lowering the threshold below the total, and the undefined "date of the purchase".
- Not verified: the other four lenses and other model families were not run for real; the revised prompt still produces some out-of-lane findings (field types) and implementation-detail noise (storage format of the month); prompt sizes ~14k chars system + ~14k user per call.

## Requests from the main orchestrator after reading the first real report (26 Nov)

Context: `uv run tekti local/requirements.md runs/board-1.md` works end to end (54 requirements, 46 findings, 39 questions). The report came out at 1,635 lines. A jury member will not read that. Please treat the following as P7/P8 follow-ups.

### P7 report
1. **Add a short opening block right after the passport**, before the segmentation table: the verdict (two yes/no lines), counts by severity, the critical defects as one line each, and the top five questions with addressee. Ten to twenty lines. Sections 6 and 7 stay where they are; this block repeats their headline so the reader gets the answer on the first screen.
2. **Per-requirement section is too long and mostly empty.** A requirement with no finding of its own should be one line (id, source id, short quote, and the "see set-level findings" pointer), not a five-line block. Children of a split requirement go directly under their parent without repeating the parent's location.
3. **Challenge reasoning:** show the verdict and at most the first two sentences; the full text stays in the run JSON.
4. **Passport:** `dropped_reviewers` entries can be long raw error texts. Show `angle / model: first 120 characters`, one per line.
5. **Fix-first and critical lists:** location once (section and line of the first quote), not every location.
6. Requirement ids in text sometimes arrive with a Cyrillic "Р" ("Р-005") from the models; normalise to Latin "R-" when rendering question and finding text.
7. `Run.raw_findings` now exists (all reviewer output before merging). Do not render it; the passport may state the count.
8. The main orchestrator is fixing adjudication so that a finding about one requirement carries exactly one requirement id (today many carry parent + child and land in the set-level section). No change needed in P7 for that, but expect section 3 to fill up and section 4 to shrink.

### P8 scorer
The anchor-overlap rule (as specified) is generous: a finding that merely quotes the same sentence counts as a hit, e.g. G-11 is "hit" by findings about other defects in Ф-2. Please add a second, stricter figure next to the current one: a hit requires anchor overlap AND a compatible criterion (same criterion, or the related pairs: correct/set_consistent, complete/set_complete, unambiguous/verifiable, verifiable/set_validatable, conforming/set_complete, singular/modifiable). Report both as "loose" and "strict" recall, and list for each gold item which finding satisfied the strict rule. Keep the unmatched-findings list on the loose rule.
